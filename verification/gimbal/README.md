# 红色矩形视觉云台控制

更新：2026-10-20。当前版本用来源帧号、图像误差变化率和帧龄预测控制转动速度，替代旧版“按方向固定步进”和“每步固定等待100 ms”。摄像头随云台转动，目标为画面中心(640,360)。这不是舵机实际角度反馈控制。

## 接线与启动

| 功能 | 顶层端口 | FPGA引脚 / 接线 |
|---|---|---|
| 水平PWM | O_servo_pan_pwm | V1，J1第2脚 |
| 俯仰PWM | O_servo_tilt_pwm | U1，J1第4脚 |
| 自动瞄准开关 | I_sw1 | A4，低电平保持，高电平跟随 |

舵机使用外部稳压5 V并与FPGA共地，不能将5 V供电线接到FPGA信号引脚。上电或复位后先输出1500 us中位约3秒；必须先采样到实际SW1关闭，再打开才允许跟随。建议保持SW1关闭上电，待画面正常后打开。关闭SW1保持当前PWM位置，不断开舵机电源、不自动回中。

用户实板反馈曾出现：SW1开启上电黑屏WAIT 1221，而关闭上电、画面正常后再开启可正常跟随。此启动保护保留，但底层原因仍未确定，不能称为已经修复DDR或供电问题。K4只控制显示叠加，六种显示模式均可后台控制。

当前顶层使用PAN_REVERSE=0、TILT_REVERSE=1（用户确认原俯仰方向相反）：目标偏左时水平脉宽增加；目标偏上时俯仰脉宽减少。2026-10-20按当前反转后的方向重设俯仰行程：水平50000～100000保持，俯仰41667～83333，中心75000；抬头为减脉宽，名义最大60度，低头为增脉宽，名义最大15度。50 MHz下1 us=50 ticks。实际机械角度和上下行程需按组装校准。

## 控制算法

每个轴独立计算，下式中的误差为“画面中心减去目标包围框中心”，单位为原图像素：

```text
e       = center - observed_center
velocity= (e - previous_e) / (sample_frame - previous_sample_frame)
age     = current_camera_frame - sample_frame
predicted_error = e + velocity * (age + LEAD_FRAMES)
rate    = clamp(predicted_error / 2^KP_SHIFT, -STEP_TICKS, +STEP_TICKS)
```

rate是每个20 ms PWM周期的脉宽变化量，不是立即跳转到一个绝对角度。PD基础速度上限STEP_TICKS=250；当前默认SPEED_BOOST=1，在PWM域对速度做对称1.5倍放大，正负均按绝对值截断，最终每周期最多375 ticks（7.5 us）。SPEED_BOOST=0可恢复基础速度。放大同时保留提前刹车与超时保护，不能等同于实测响应时间必然缩短50%。误差大时较快，接近中心时比例项自然减小；误差正快速缩小时，变化率项提前减速。预测若已越过中心，仅将该方向速度压到0，不允许因预测值单独反向追赶。实际误差进入停止区域也输出0。没有固定的逐步等待，限幅处不会累积额外位置积分。

保留X±24、Y±20的停止区域；停止后对应误差须超出X±36、Y±30才重新启动。小于1 tick但仍应纠偏的比例输出取±1 tick，避免调低增益后量化导致永久停在停止范围之外。

默认LEAD_FRAMES=2，用于附加的控制/机械响应预测；帧龄来自实际来源帧，变化率按两次检测的真实来源帧间隔归一化，不假设检测每帧更新。LEAD_FRAMES不是实测机械延迟，也不是LAT面板数值。它和KP_SHIFT仍需实板校准，不能保证所有相机视场、负载和移动目标下都稳定。

## 目标与帧关联

- 复用现有AWB后红色RECT跟踪槽，先取最小合格ID，然后保留该ID；暂失held时停止，避免切到另一个框。槽清除后才重新选择。
- ISP在AWB SOF计数camera_frame_id，在CCL真正接受降采样掩码首样本时保存captured_frame_id；raw检测发布时锁存result_frame_id，随跟踪输出供控制器使用。分析忙时跳过的摄像头帧不会被误认为新结果。
- 16位来源帧号按模65536处理。重复帧、倒序帧、超龄帧不能刷新有效速度；换ID、漏检/暂失后清除速度历史；间隔超过MAX_SAMPLE_GAP时不沿用旧变化率。
- 默认MAX_SAMPLE_AGE=8；按当前720p60配置，将剩余来源帧预算折算为50 Hz PWM周期，并叠加STALE_FRAMES=6的接收端看门狗。有效期内保持速度命令，到期后停止积分。低帧率、传感器停帧或长时间无结果会保持位置。
- 换成其他摄像头帧率时必须重新审查有效期换算，不能原样套用60 fps假设。

## 实现与资源边界

`user_source/hdl_source/red_rect_gimbal.v`包含顶层控制及gimbal_pd_rate计算单元。两轴的PD速度计算共用重复加法与16拍串行除法路径，PWM域分别执行两轴位置限幅。RTL没有动态乘法或除法操作符；最新综合层次报告确认云台为0 ERAM、0 DSP。813组数值参考测试中最长57个检测时钟完成一次两轴计算；检测更新需至少间隔128个检测时钟，正常CCL/跟踪生产者远慢于此。忙时的新更新不排队。

算法输出通过23位req/ack邮箱提交到50 MHz PWM域，内容为有效位、4位有效期、两路9位有符号速度；不是逐位异步采样坐标。源端保持负载至应答返回，请求/应答双级同步，复位分别同步释放。旧7位方向协议已替换。

SDC未改变：现有MIPI与系统时钟异步分组保留，两条u_latency/u_pixel_time/ack1与req1入口例外保留。新Run必须检查云台邮箱第二同步级Setup/Hold、同步器放置和23位负载在请求同步窗口内的稳定性。RTL仿真不能验证亚稳态或物理负载延迟。

用户本地最新资源报告为2026-10-20 19:19:31：20315/21216 Slice（95.75%，余901）、19093 LUT6、22321寄存器、83 ERAM、26 DSP；19:19:28时序报告SWNS +0.119 ns、HWNS +0.020 ns、STA coverage 95.19%。综合层次包含red_rect_gimbal与gimbal_pd_rate，云台合计490逻辑LUT、236 ripple、346寄存器、0 ERAM/0 DSP。本文未建立源码与bit哈希对应，报告只能证明该次本地构建，不能替代机械行程和跟踪稳定性的实板验收。生成文件不随本次发布更新。

主要参数范围：SPEED_BOOST为0或1；STEP_TICKS为1～255（启用放大后的最终速度约为基础的1.5倍）；KP_SHIFT为0～8（越大比例速度越低）；LEAD_FRAMES为0～8且MAX_SAMPLE_AGE-1+LEAD_FRAMES≤15；MAX_SAMPLE_AGE为2～8；MAX_SAMPLE_GAP为1～255；STARTUP_FRAMES、STALE_FRAMES不超过255；脉宽限幅应包含中心并小于FRAME_TICKS。
