# 采集至 HDMI 延迟可视化

更新：2026-10-11。

## 屏幕显示

HDMI 输出端左下角 x=16..367、y=608..671，黑底青字四行，使用现有16×16字库。

```text
CAP  0000000102 FR
DISP 0000000100 FR
AGE  0000000002 FR
LAT  0000040.2 MS
```

以上仅为格式示例，不是实板测量。

当前摄像头使用1280×720@60初始化。60 fps时AGE=2意味着显示的来源帧开始于约33.3～50 ms前，LAT应与这个量级相符；AGE不是固定的两帧毫秒常量，也不能套用备用全分辨率30 fps配置。用户反馈AGE=2、LAT约30～40 ms，实际帧率及测量精度仍需外部核对。

- CAP：本次显示开始时最新的采集帧编号，十进制，10位覆盖完整32位计数范围。
- DISP：当前显示画面对应的采集帧编号，十进制；不是独立的显示端计数。
- AGE：CAP−DISP，十进制帧龄，按32位模减计算。
- LAT：对应画面从 CSI 帧开始到 HDMI 输出端首个有效像素的时间，单位毫秒，截断显示至0.1 ms。
- WAIT：本帧无法提供可信测量。启动未填满、未完整写入、元数据缺失、FIFO异常或关联错误均不显示正常数值。
- 无效时LAT行显示 `WAIT xxxx`，xxxx为16位十六进制原因码，各位可以同时置1，见下表。

数值每个显示帧锁存一次；帧内新发生的读空或写覆盖会立即使测量失效。延迟面板始终开启，不受k4控制；没有改变按键和sw1功能。

2026-10-11：帧号改为十进制，避免出现A..F；数字4改为与其他数字相同的12行高度和底线，字符单元仍为16×16。CAP、DISP、AGE和LAT共用一个移位加3转换器，每个数32拍、四个数128拍，在75 MHz下约1.7微秒，远早于第608行面板显示。十六进制帧号可省去格式转换，但这段转换不会阻塞视频流或增加采集到显示的延迟。WAIT原因码仍保留十六进制含义。

## 测量口径和实现

统一时间基准为 `I_sys_clk`，现有SDC定义50 MHz。计时器每50拍增加1微秒，32位约71.58分钟回绕；采用无符号减法支持跨回绕测量，拒绝时间差或帧差最高位为1的异常值。

计时器每微秒通过握手邮箱分别发布稳定快照到CSI和HDMI时钟域。时间戳存在1微秒量化及邮箱传输/时钟相位误差，因此不是纳秒级计量；异步集成仿真使用±2微秒参考容差，实际精度还需实板核对。

`S_csi_frame_start` 给新帧编号并记录时间，RAW SOF绑定当前CSI标签，ISP输出SOF消费该标签。当前实时流水线要求对应ISP SOF先于下一帧RAW SOF到达；丢失、重复或重叠的SOF触发保守失效，避免静默错帧。AWB提前SOF约定、valid、last和算法数据路径不变。

标签经握手邮箱送至DDR域，与 `video_in` 同一个帧开始事件以及地址块实际使用的更新前写指针绑定。四槽元数据分别存储来源帧号、采集时间和有效标志。无论标签还是槽位事件先到，都等待两者齐备后关联。

完整帧条件为内存控制器实际发出的172800个连续128位写命令：

```text
1280 × 720 × 24 / 128 = 172800
```

监控使用 `S_mc_app_wdf_wren` 与 `S_mc_app_addr`，而非仅统计输入FIFO或DDR请求队列的接收数量。新写入先清除该槽的旧有效性；未写完、乱序/重复写入的槽不能发布有效延迟。此检查验证连续写命令数量，并不证明图像内容、CSI包完整性或显示器接收正确。

`video_out` 选读基地址的同一个事件锁存对应槽元数据，再通过邮箱送到HDMI域。显示端在首个有效像素处相减并锁存数据，之后进行十进制转换和文字叠加。重复显示同一槽时DISP保持相同，时间差重新测量。

OSD增加一拍像素时钟寄存，RGB、DE、HS、VS一起延迟；同步后的输出直接接 `hdmi_tx`。测量终点位于延迟OSD的输出寄存级，属于HDMI编码前的数字视频接口，不包含TMDS编码器内部各级、线缆、显示器处理及面板响应，也不包含CSI接收前的曝光和传感器内部延迟。

邮箱握手使用两级控制信号同步并额外等待一拍再读取稳定负载；负载直到应答返回才允许变化。实现时仍须检查同步器保留和放置、稳定负载路径，以及现有异步时钟组约束。正常时钟下每微秒尝试发布一次时间快照；时间邮箱忙时跳过本次发布并等待，不将摄像头时钟尚未启动当成永久错误。CSI和HDMI端各收到两个时间快照后才允许测量，第一份可能在接收时钟启动前已被发送。采集时的时间有效性跟随该帧保存，之后的时间就绪不会追认之前的无效帧。

2026-10-11修复：原代码无条件每微秒发送，CSI时钟在摄像头配置期间未运行时，第二次发送会触发永久邮箱错误。旧代码在CSI晚启动0.1 ms的仿真中已复现此故障；修复后同场景自动恢复并显示有效测量。不修改sw1，仍采用自动测量；只有后续实板验证仍有问题时才考虑开关触发。

## 异常与诊断

- 未填满、未完整写入或暂缺元数据：本帧WAIT，后续完整帧可恢复。
- 输入FIFO溢出、SOF关联失败、邮箱覆盖或DDR写序列错误：保守保持WAIT直到系统复位。
- 输出FIFO读空、当前显示槽被覆盖：本帧WAIT，下次重新选读有效槽后可恢复。
- 仿真/实板诊断可查看 `u_latency` 下的 `measure_valid`、`latency_us`、`frame_age`、`display_id` 和 `faults2`；后者位8..0依次为CSI时间邮箱、HDMI时间邮箱、帧号邮箱、输入溢出、SOF关联、采集元数据邮箱、槽序列、显示元数据邮箱、读槽失效。
- 检测分支的跳帧及类别稳定耗时未纳入单独指标；LAT只描述视频画面链路。

| 原因位掩码 | 含义 |
|---|---|
| 0001 | 所选读槽未完成、来源标签无效或读写覆盖 |
| 0002 | 显示元数据邮箱覆盖 |
| 0004 | DDR写序列或标签/槽位配对错误 |
| 0008 | 采集元数据邮箱覆盖 |
| 0010 | CSI/RAW/ISP帧开始关联错误 |
| 0020 | 输入FIFO溢出 |
| 0040 | 最新帧编号邮箱覆盖 |
| 0080 | HDMI时间邮箱错误，修复后正常发送条件不应触发 |
| 0100 | CSI时间邮箱错误，修复后正常发送条件不应触发 |
| 0200 | 本帧输出FIFO读空 |
| 0400 | 时间快照尚未就绪 |
| 0800 | 本次显示帧开始前未收到对应元数据 |
| 1000 | 显示画面的元数据无效 |
| 2000 | 时间差异常（最高位为1） |
| 4000 | 帧龄异常（最高位为1） |

高位条件在显示帧开始时锁存，低11位还反映当前故障状态。例如 `1001` 同时表示读槽无效和来源标签无效，启动阶段可能暂时出现；不应通过屏蔽有效性检查来强行显示数值。
