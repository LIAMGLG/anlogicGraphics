# 纯FPGA红绿颜色块与简单形状检测

更新：2026-10-11。采用传统整数算法，无CPU或CNN。当前只检测红色、绿色，蓝色主导区域作为背景；主画面的蓝色正常显示。

## 算法与参数

检测链路：`AWB RGB → 4×4均值 → 320×180红绿掩码 → 四连通域 → 面积/尺寸过滤 → 最大四区域 → 外轮廓与多边形分类 → 类别稳定 → OSD`。

| 项目 | 当前值/行为 |
|---|---|
| 输入 | AWB原始输出，独立于显示增益、饱和度及模式 |
| 红色参数 | RED_MIN=40、RED_MARGIN=12 |
| 绿色参数 | COLOR_MIN=40、COLOR_MARGIN=12 |
| 相对优势 | 主通道比另外两通道各高至少自身值的25% |
| 最小区域 | 面积25个掩码像素，宽高各至少5 |
| 标签容量 | 31个有效槽，0为背景 |
| 输出数量 | 面积最大的4个区域；N/R/G为这些区域的数量 |
| 坐标映射 | 最小坐标×4，最大坐标×4+3 |
| 类别稳定 | 改变类别需连续3次确认；首次直接显示，消失/溢出清除 |

颜色分割要求主通道达到亮度下限，并领先另外两通道至少 `max(绝对差,ceil(主通道/4))`。
保留B通道平均值用于红绿比较。降低亮度或差值门槛更容易接受暗色，也可能增加噪点；白平衡、光照和反射会改变实际RGB比例。

CCL按同色左/上邻居查根并合并面积、包围框和种子。四连通使对角相接区域分离，同色粘连区域会合并。
行末回收已消失的不足面积区域；对大目标合并别名，先解析父链、规范化全部行缓存引用，再释放别名槽，避免复用产生悬空引用。
标签并发峰值或保留的大区域过多仍可能耗尽容量；**LABEL OVERFLOW会清空该次全部检测结果**。
面积过滤不是形态学开闭运算，当前未实现形态学处理。

轮廓核对前四区域进行Moore外轮廓跟踪、闭合Douglas–Peucker近似、角点清理、凸性/角度/面积/圆度检查：

- 三顶点：TRIANGLE。
- 四顶点且角度通过：RECT。
- 5～12顶点且圆度通过：CIRCLE。
- 其他或跟踪失败：UNKNOWN。

轮廓点RAM深度2048，DP堆栈16项；使用近似欧氏距离和随链码周长变化的容差。
大孔洞、边界裁剪、非凸、轮廓/堆栈超限可能被拒绝。近圆多边形和一般四边形仍可能混淆。

## 显示与诊断

k4切换检测框、编号、图例、计数、MASK和V/E诊断，默认开启；关闭叠加不会停止分析。
检测结果与使能在显示SOF锁存，同一帧保持一致。显示模式操作见 [显示 README](../edge_modes/README.md)。

- 计数：x=16..271、y=64..79；图例：y=96..159。
- V/E诊断：x=16..271、y=176..239，按目标编号显示原始顶点数V和拒绝码E。
- MASK V4：右上角x=944..1263、y=16..195；红/绿为分割结果，黑色为背景。
  它是CCL实际采集的掩码，不是缩小的彩色视频，也不保证每帧刷新。
- 三银行预览RAM保护采集、等待提交和显示；CCL主掩码RAM仍是单读/单写，分析期间不能覆盖。

| E | 含义 |
|---|---|
| 0 | 接受 |
| 1 | 目标接触掩码边界 |
| 2 | 轮廓跟踪失败或超时 |
| 3 | 轮廓点容量耗尽 |
| 4 | DP堆栈容量耗尽 |
| 5 | 非凸 |
| 6 | 面积/孔洞检查失败 |
| 7 | 顶点数量不支持 |
| 8 | 四边形角度未通过 |
| 9 | 圆度未通过 |

MASK中目标缺失/破损时先查颜色分割；完整但无框时先看LABEL OVERFLOW，再看区域面积/尺寸过滤；有框但类别不对时看V/E。
UNKNOWN本身不会禁止画框。最终类别经过稳定处理，可能短暂与原始V/E不同。

## 限制与验证状态

实拍仍受暗光、偏色、反光、模糊、遮挡、粘连和目标大小影响，旋转/尺度稳定性尚未确认。
检测忙时跳过新帧，结果及框可能滞后；类别关联不是完整运动跟踪，同色目标交叉可能关联错误。

**当前红绿参数、合并别名回收和更新后的全ISP尚未完整重跑回归。**用户已完成2026-10-11 12:38 TD实现，整机19163/21216 Slice、73/108 ERAM、26/40 DSP，Setup +0.155 ns、Hold +0.020 ns。

当前颜色/形状检测模块含轮廓，占2927个逻辑LUT、482个加法器资源、2670个寄存器、10块ERAM、17个DSP；其中轮廓占1358个逻辑LUT、402个加法器资源、1244个寄存器、2块ERAM、16个DSP。包含关系不能重复累计，详见 [资源 README](../resources/README.md)。

历史MASK V4曾通过检测回归及1731个几何公式轮廓场景；这是人工合成，不是实拍准确率，也不能代替当前版本回归。当前只落实Logo资源压缩，轮廓乘法器复用和位宽缩减尚未修改；坐标已为9/8位，减少标签或轮廓容量会改变可检测范围。

## 手动复现

从工程根目录执行；TD Run由用户完成，以下为可选手动命令：

```powershell
powershell -ExecutionPolicy Bypass -File verification/shape_detection/run_sim.ps1
powershell -ExecutionPolicy Bypass -File verification/shape_detection/run_sim.ps1 -Only tb_color_shape
powershell -ExecutionPolicy Bypass -File verification/shape_detection/check_synthesis.ps1 -Implement
```

仿真支持 `-ModelSimBin`，检查退出码和PASS。覆盖颜色平均/阈值、独立BFS核对CCL、合成轮廓、稳定器、逐像素OSD/MASK和全720p ISP。
核心测试保留三色编码兼容性场景；当前全ISP预期蓝圆被忽略，显示三个红绿目标。demosaic/AWB使用替身，不验证真实摄像头、AWB算术、DDR或HDMI。

综合脚本支持 `-TdBin`，使用独立 `work_syn_v4` 目录，`-Implement`包括布局布线与bitgen，并检查新鲜报告、资源容量及最终时序。
输出文件名仍为 `work_syn_v4/shape_mask_v4.bit`；运行会更新该目录，文件名和MASK V4标题不能证明其对应当前源码。旧bit与构建目录可能仅本地存在，不能作为克隆工程的前置依赖。
