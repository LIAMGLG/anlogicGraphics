## 实际硬件算法

`AWB RGB888 → 4×4 均值 → 颜色掩码 RAM → 四连通域 + union/find → 面积过滤 → 最大四区域 → 外轮廓/多边形分类 → 类别稳定 → OSD`。

- `color_reduce_rgb96.v`：四像素组横向相加，行 RAM 累计四行，除以 16 取整，输出 320×180。
  主通道至少 80，且比另外两个通道各高至少 32，分别判为 RED/GREEN/BLUE，否则背景。
  加法比较扩展位宽，避免亮色加裕量后溢出。COLOR_MIN/COLOR_MARGIN 可配置。
- `color_shape_detect.v`：在空闲时采集完整 2bit 掩码帧，分析时不写掩码 RAM。
  按行扫描，同色左/上邻居执行标签查根与合并，同时合并面积、包围框。
  不同颜色相接仍是不同区域；同色四邻接目标会合并，对角接触保持分离。
  首版标签表 32 项，其中 0 是背景，最多分配 31 个临时标签。
  **临时标签数量不等于最终目标数量**：细碎噪声或多分支区域也会耗尽标签。
  耗尽时整次结果清空并输出 LABEL OVERFLOW，避免显示不完整计数。
  默认面积 ≥25 个缩小像素，宽和高各 ≥5；均值与区域面积过滤用于抑制噪点。
  未实现开闭运算，不能把面积过滤描述为形态学处理。
- `shape_contour_classifier.v`：从每个 CCL 根保存的“最上行最左像素”开始 Moore 外轮廓跟踪，
  2048×17bit 轮廓点缓存使用单读/单写同步 RAM；最多保存 2047 个边界像素及闭合点。
  只跟踪被选中的四个目标，不扫描全场每个噪点的轮廓。
  闭合 Douglas–Peucker 分成两条链、16 项堆栈，按目标尺寸选择距离容差，
  增加半像素量化容差并清理近共线点及短假边，避免起始点/像素阶梯多出顶点。
  凸三角形近似 → TRIANGLE；凸四边形且角度约 53..127° → RECT，允许轻微透视；
  5..12 顶点、较高圆度 → CIRCLE。其他 UNKNOWN。
  周长使用正交步长 256、对角步长 362 的 Q8 链码；以 `P² ≤16A` 作圆度门槛，
  不需要平方根或除法，也不再要求圆形的水平包围框接近正方形。
  CCL 面积至少为近似外轮廓面积的 80%，大孔洞/环形被拒绝，小内部缺色允许保留。
  接触画面边界、轮廓容量耗尽、堆栈溢出、超时或非凸近似输出 UNKNOWN。
  **仍是针对简单色块的分类器**：近圆多边形可能被判为圆，一般四边形可能被判为 RECT；
  遮挡、严重倾斜、接触/粘连、颜色分割破损和非常小的目标仍会失败。
  建议完整可见、背景分离、尺寸至少约 64 原图像素；容差针对 320×180 掩码像素。
- `detection_result_stabilizer.v`：按颜色和最近中心关联相邻检测结果，类别改变需连续三次确认。
  首次出现直接显示类别，坐标/数量随最新检测更新，消失/溢出立即清除；
  连续三次 UNKNOWN 也会清除旧类别，不会无限保留旧判断。
  该处理只抑制类别抖动，不是完整运动跟踪；同色交叉目标可能关联错误，
  有意改变形状时会多等待两次检测更新。
- 最多保留面积最大的 4 个区域，坐标按 `min*4` 和 `max*4+3` 映射到原画面。
  N、R、G、B 是**当前显示的四个以内目标**的数量，不代表超过四个时全场总数。
- 检测分析不阻塞视频；忙时跳过新检测帧，保留最近结果。
  结果发布时间与下一次显示 SOF 之间存在延迟，运动目标的框会滞后。
  不保证逐帧检测；只做类别稳定关联，没有速度预测或置信度估计。

## 显示与操作

原模式名称 OSD 保留。检测结果在其后、DDR 打包前叠加，数据与控制再延迟三拍。
SOF 整体锁存检测框、显示数量、错误状态和使能；同一帧中不更换结果。
检测输入始终是 AWB 后 RGB，与正常/二值化/边缘/卡通显示模式独立。
卡通本身的空间平移仍存在，因此卡通画面与原图坐标框存在原有的小偏移。

- k1/k2/k3、sw1 原功能保留，包括 k2/k3 同时影响摄像头增益的既有限制。
- k4（I_button[3]，C7，低有效）消抖后切换检测叠加，在下一显示帧生效。
- 上电默认开启检测叠加；关闭叠加不会停止检测分析，模式名称仍显示。
- 框为红/绿/蓝，左上角带白色编号 1..4。左侧图例按编号显示颜色和 RECT/CIRCLE/TRIANGLE/UNKNOWN。
- 计数面板在 x=16..271、y=64..79，图例在 y=96..159；会遮挡对应区域的视频。

## 复现验证

在工程根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File verification/edge_modes/run_sim.ps1
powershell -ExecutionPolicy Bypass -File verification/shape_detection/run_sim.ps1
powershell -ExecutionPolicy Bypass -File verification/shape_detection/check_synthesis.ps1
```

仿真脚本支持 `-ModelSimBin` 和 `-Only tb_shape_contour` 等单项测试，同时检查退出码和 PASS 标记。
综合脚本支持 `-TdBin`，从主 .al 生成独立 work_syn 工程；不覆盖主工程运行目录和 bit。

1. `tb_color_reduce`：逐样本对照 4×4 平均、RGB 比较边界、亮色溢出、噪点、坐标和 SOF/valid 间隔。
2. `tb_color_shape`：独立 BFS 参考检查矩形/圆形、同色多目标、合并、不同颜色相接、对角分离、
   面积排序、边界、环形未知目标、噪点、标签溢出、忙时跳帧、复位，另检查旋转矩形/三角形与缺色圆形的 CCL 种子接入。
3. `tb_detection_overlay`：逐像素检查框、编号、文字、计数、溢出提示，帧内结果/使能不变与三拍控制延迟。
4. `tb_shape_contour`：291 个独立几何场景，矩形/圆形/三角形每 15° 一组、四种尺寸、
   轻微仿射倾斜，大圆形占画面高度约 95%，另含环形拒绝和小孔洞矩形。
5. `tb_detection_stability`：类别短暂跳变、连续三次确认、移动、同色关联、排名交换、
   UNKNOWN 过期、目标消失、溢出与复位。
6. `tb_detection_isp`：完整 1280×720 合成帧，验证三颜色四目标（矩形/圆形/三角形）、
   缩放坐标、稳定结果帧提交与真实 k4 消抖。
   demosaic/AWB 使用仿真替身，不覆盖真实摄像头、AWB 算术、DDR 或 HDMI 硬核。

## MASK V3：方向/尺度容差与实物诊断（2026-10-09，历史版本）

用户已下载前一轮廓版，但反馈角度/尺寸仍敏感，决定继续传统算法。
本版 DP 距离改用 `max(abs(dx),abs(dy)) + 3*min(abs(dx),abs(dy))/8` 近似欧氏长度，
方向误差小于 7%；原 L1 长度的方向差异约 41%。尺度容差用 Q4 链码周长连续推导，
代替水平包围框大小分档，带一个掩码像素的下限。容差长度、乘积、移位相加分拍执行；
不增加多周期或假路径约束。角点/凸性/面积/圆度检查和三次类别稳定保持。

**测试场景由 `tb_shape_contour.sv` 的几何公式生成，不是摄像头实拍或开源数据集。**
1731 场景：矩形/圆形测试 0..175 度，三角形测试 0..355 度，均每 5 度，
半径尺度 8/12/20/32/48/60、亚像素中心及两种倾斜，
另有半径 85 完整大圆、环形拒绝和小孔矩形。只能证明这些输入下 RTL 正确，
没有验证真实光照、反光、模糊、AWB 和颜色掩码破损；不得将其表述为实物准确率。

新 `detection_mask_osd_rgb96.v` 在右上角显示实际接受的 320x180 颜色掩码：
x944..1263/y16..195，白框，下面为 **MASK V3**。红/绿/蓝是分割结果、黑色是背景。
不是缩小的原始 RGB 图像。独立三银行 RAM 避免正在采集、等待帧提交与显示互相覆盖，
不增加主 CCL 掩码读口。与稳定结果一起发布、显示 SOF 提交，存在检测延迟。
模块增加两拍视频/控制延迟，随后原检测 overlay 仍为三拍；k4 一起开关两者。

左侧 y176..239 的四行 `1 V:04 E:0` 等诊断对应目标编号。
V 为原始轮廓近似顶点数，最多显示 15；E 是原始分类拒绝码，最终类别经过稳定确认，
所以瞬间可能与 V/E 不同。不存在目标时不显示该行，标签溢出仍有独立提示。

| E | 含义 |
|---|---|
| 0 | 接受 |
| 1 | 目标接触掩码边界 |
| 2 | 轮廓跟踪失败或超时 |
| 3 | 轮廓点容量耗尽 |
| 4 | DP 堆栈容量耗尽 |
| 5 | 简化轮廓非凸 |
| 6 | 区域面积不足，可能有大孔洞/缺色 |
| 7 | 顶点数量不支持或过于复杂 |
| 8 | 四边形角度未通过 |
| 9 | 圆度未通过 |
