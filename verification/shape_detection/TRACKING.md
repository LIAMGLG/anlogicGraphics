# 四目标轻量跨帧跟踪

更新：2026-10-13。实现位于 `user_source/hdl_source/isp/target_tracker.v`，已经接入实际ISP路径。源码与ModelSim验证完成；本次没有运行TD、生成或下载bit。资源、Setup/Hold和实拍跟随效果待当前源码完整实现及上板确认。

## 原理和路径

`AWB → 4×4均值 → 红绿分割 → 连通域最大四区域 → 轮廓分类 → target_tracker → MASK/检测叠加 → Logo → DDR → HDMI`。

跟踪器替代ISP中的旧类别稳定器，保存四个固定槽。框上的1～4号表示槽编号，目标关联成功时保持编号，面积排名变化不改变编号。目标清除后编号可复用，不是全局唯一身份。

每次完整检测结果锁存后，顺序比较最多16对候选，反复选择全局最小距离的有效配对，已配对的输入和槽不能再次使用。这是确定性的最近距离贪心关联，不是全局最优组合求解。

候选必须同色、槽未超时、宽高变化不超过4倍。距离使用两倍中心的曼哈顿距离，不需要除法：

`dx = (new_xmin + new_xmax) - (old_xmin + old_xmax)`，y同理；

`distance = abs(dx) + abs(dy)`。

每个轴的门限为 `new_size + old_size + 2*MATCH_MARGIN`，等价于中心移动不超过两框尺寸平均值加余量。初版不计算IoU，形状不作硬匹配条件，防止单次误分类破坏身份关联。

匹配成功时直接更新坐标；改变既有类别需要三次连续匹配检测确认，UNKNOWN也遵循该规则。未匹配会打断类别确认序列。内部轮廓诊断按输入到槽的配对关系重排，供仿真检查；画面已移除V/E，显示中心坐标。

## 状态与参数

| 参数 | 默认值 | 作用 |
|---|---:|---|
| STABLE_UPDATES | 3 | 类别改变的连续确认次数；支持1～7 |
| MAX_MISSES | 2 | 容许两次完整检测漏检，第三次清除；支持0～254 |
| MAX_HOLD_FRAMES | 12 | 自最后成功发布起最多保留12次AWB SOF；支持1～255 |
| MATCH_MARGIN | 32 | 原图像素单位的额外匹配余量 |

60 fps且SOF连续时，12帧约200 ms。这里的计时从结果发布起算，不是曝光或采集时刻；检测忙时跳帧不增加漏检次数，但视频SOF仍推进超时计数。没有SOF时帧计时也不会推进。

| 状态 | 画面与计数 |
|---|---|
| 当前匹配或新建 | 原颜色实线框、固定编号、颜色及稳定形状文字；计入N/R/G |
| 暂时丢失 | 最后位置的灰色虚线框、原编号、颜色和WAIT；不计入N/R/G，显示最后位置的中心坐标 |
| 第三次漏检或帧超时 | 清除框、文字和槽状态，编号可复用 |
| LABEL OVERFLOW | 保留原告警，将旧目标标为暂失，不创建新目标、不增加普通漏检次数；帧超时仍有效 |

四个槽包含暂失目标。槽满时，新目标暂时不能建立跟踪，待旧槽释放后再接收；N/R/G是本次成功建立或匹配的目标数，而非所有输入区域的无条件计数。显示允许空槽，例如只剩3号时仍显示3号，不压缩为1号。

跟踪器输出统一发布，叠加模块在显示SOF锁存框、暂失状态、数量和坐标输入，同一帧不随输入变化。原叠加仍为三拍，视频总流水线延迟不变。检测掩码银行仅由真实检测结果更新触发；帧超时清框不额外发布掩码。

## 资源与时序边界

新增逻辑仅使用现有ISP时钟域，无整帧缓存，无运行时乘除运算，设计目标为新增0 ERAM、0 DSP。四槽状态使用寄存器；16对比较共用顺序处理逻辑。

当前单元场景实测最长178周期，75 MHz下约2.37 μs。按四次成功匹配、五轮候选扫描及最慢分配路径计算，处理上界小于256周期；生产端相邻更新必须至少间隔256周期，CCL完整分析满足这一约束。该周期数不是图像端到端延迟，检测分析耗时和DDR帧龄仍存在。

数百LUT和约500～1200寄存器只是方案预算，不能作为综合报告。旧类别稳定器仍保留源文件和独立回归，但TD工程和ISP已使用新跟踪器；两者不同时进入实际链路。

没有改动SDC、邮箱req1/ack1、同步器层级或基础AWB模块。当前工程中的两个第一级入口例外须保留，新完整Run仍需检查对象匹配、第二级Setup/Hold与最终报告。已有数据库的时序不能证明新RTL通过。

## 实板展示

用户重新TD Run并下载新bit后，在NORMAL模式且k4叠加开启时：

1. 用红矩形、绿圆或绿矩形、红三角建立目标。缓慢移动，记录框与固定编号。
2. 改变距离或大小，让两个目标面积排名交换，验证编号仍随各自目标。
3. 短暂遮挡一个目标，观察灰色虚线和WAIT；在有效保留期内恢复，检查原编号恢复。
4. 移出目标，确认达到漏检或帧超时门限后撤框。新目标进入后可使用释放的编号。
5. 切换六种显示模式，检查原功能；MOTION仍显示独立黄色运动区域，红绿跟踪叠加被隐藏。

建议录制上述过程并记录是否出现编号交换、旧框残留、位置滞后和丢失恢复。不要用单张静态截图替代动态跟踪演示。


## 中心坐标显示（替换V/E）

原左侧V/E区域x=16..271/y=176..239改为四行中心坐标：`1 X:0320 Y:0220`，编号与框一致。X向右、Y向下，左上角(0,0)，单位为1280×720原图像素。显示框中心而非质心，计算为 `X=(xmin+xmax)>>1`、`Y=(ymin+ymax)>>1`；小数部分向下取整，四位十进制补零。包围框仍来自4×4降采样，不意味着检测具有单像素测量精度。

目标暂失时该行保持最后坐标，同时形状图例显示WAIT、框为灰色虚线；目标清除后坐标行撤去。k4控制整个叠加，MOTION模式仍隐藏红绿目标坐标。

四个目标的八个数值共用一个12位移位加3BCD转换器，无除法和新增视频缓存。显示SOF同时锁存框及中心输入，104拍后统一提交全部坐标数字；75 MHz下约1.39 μs，远早于第176行。连续提前SOF会重新启动转换，完成前坐标面板不绘制旧数字。原三拍视频叠加延迟不变，未改CDC/SDC。转换逻辑及寄存器净开销需TD确认，本次未运行TD或生成bit。

ModelSim坐标专项覆盖全部X=0..1279、Y=0..719、半像素向下取整、999/1000进位、八项共享转换、104拍、输入快照、统一提交、提前SOF重启及复位；六帧逐像素显示验证坐标字符、固定空槽编号、暂失及帧内输入变化；四次720p实际检测ISP验证移动/排序变化/漏检恢复时坐标与框一致。六模式及运动ISP同步回归。

## 后续优化

同色目标交叉、严重遮挡、粘连、突然大位移和剧烈尺寸变化仍可能产生错误关联。初版没有速度预测、位置平滑或遮挡分离，不承诺这些场景保持身份。

优先根据实拍调整匹配余量及保留期，再考虑按实际检测间隔做速度预测、形状/尺寸软评分、四目标小规模最优匹配。四槽全部暂失时可进一步考虑让新检测抢占最旧暂失槽；提高CCL更新频率则需要单独评估资源、掩码银行及分析吞吐。
